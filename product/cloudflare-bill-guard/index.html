The problem

Workers Paid costs $5 a month — and that is not a cap. Everything above the included amounts is metered, uncapped, and billed per unit. A hobbyist running a non-commercial project on Workers and D1 got a $2,129 bill against an expected budget of ~$20/month — an unindexed GROUP BY query scanned ~877,000 rows to return 30, an unintended loop ran it ~315,000 times, and 1.44 trillion rows were read in a single cycle (October invoice $529.88, November invoice $1,599.12). A budget alert fired once at $37 and did nothing to stop it. After a $953.74 courtesy credit, $645.38 was still due — on top of the $529.88 already paid. A developer posted a ~$35,000 Cloudflare bill for a side project with 81 users — KV writes 3.13B ($15,635), KV reads 16.62B ($8,306), Durable Object storage writes 4.01B ($3,962), KV list operations 574M ($2,870). Bots hammering a public D1 lookup produced a $300 D1 bill in days. The cause: D1 bills rows scanned, not rows returned — and a budget alert is not a brake. Cloudflare shipped real Spend Management on November 13, 2026, but only for Workers and Durable Objects. D1, R2 and KV still have no hard spending cap.

What it does

  • Audits the repo before you deploy — finds every wrangler.toml, lists D1/KV/R2 bindings, flags cron triggers (a 1-minute cron is 43,200 invocations a month with zero traffic), and checks schema files for a missing CREATE INDEX.
  • Prices the month from your real dashboard usage — Workers requests and CPU time, D1 rows read/written and storage, R2 storage and Class A/B operations, KV reads/writes/deletes/lists and storage — at Cloudflare's published November 2026 rates, with R2's whole-GB / whole-million rounding applied the way Cloudflare does it.
  • Projects the month-end total mid-month — rate meters scale with days, storage levels do not, so a day-10 snapshot becomes a month-end number while there is still time to fix the query.
  • Prices any single D1 query — rows scanned per run × runs per day, with the scan amplification that makes D1 bills explode, and a reality check against the real $2,129 invoice.
  • Sets the cap that actually stops the meter — the exact Spend Management setup (dashboard path and cf billing spend-policies create command) for Workers and Durable Objects, plus the per-product usage notifications that are the only defence for D1, R2 and KV, which have no hard cap.

Worked example — real output

A hobby project's full month of usage (45M Worker requests, 900B D1 rows read, 40 GB in R2, 40M KV reads), priced by the included script: Workers subtotal $18.50 ($5.00 base + $10.50 requests + $3.00 CPU time), D1 subtotal $875.00 (900B rows read), R2 subtotal $19.35, KV subtotal $22.50 — estimated month total $935.35 (before tax). Dominant driver: D1 subtotal is 94% of the bill. The same usage, seen on day 10 instead of after the invoice, projects to a $2,884.05 month-end total. One query, priced before it ships — the pattern from the $2,129 post-mortem (877,000 rows scanned to return 30, 10,500 runs a day): 315,000 runs/month, 276,255,000,000 rows read/month, scan amplification 29,233x, D1 rows-read cost $251.25/month (plus the $5 Workers base). Checked against the real invoice, the script prices the reported 1,447,580,203,670 rows read at $1,422.58, against the invoiced D1 rows-read line of $1,447.58 — $25.00 below the invoice, exactly the 25B included allowance.

This is the output of the included script on the stated inputs, not a promise for your setup. Your numbers will differ; the skill prices yours.

Honest limits

  • The skill prices usage from a snapshot you paste from the dashboard and Cloudflare's published rates as read in November 2026. It cannot see your Cloudflare billing page, your real usage, or your spend settings — check Billing > Billable Usage and Billing > Spend limits in the dashboard before paying for anything.
  • The estimate is a floor, not a ceiling: it subtracts each included allowance once, and against the real $2,129 case it lands $25.00 below the invoiced D1 line.
  • Spend limits exist only for Workers and Durable Objects; D1, R2 and KV have no hard cap.
  • Durable Objects are not priced by the script — their meter is separate.
  • Rates change — verify on developers.cloudflare.com. This skill reduces surprise bills. It does not guarantee any saving, and it never executes a payment or changes your Cloudflare plan or settings.
